# Identified Role & Functional Issues

| Module | Page Path | File Location | Element | Issue Category | Details | Required Action | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Deals | /deals | app/(dashboard)/deals/page.tsx | Kanban Board (Drag & Drop) | Permission Issue | `handleDragEnd` allows modifying deal stage without verifying user permissions (owner/admin). Any user can drag any deal. | Add `canEdit` check in `handleDragEnd` or disable drag for unauthorized users. | DONE |
| Projects | /projects/[id] | app/(dashboard)/projects/[id]/page.tsx | Edit Project Button | Permission Issue | The "Edit Project" button is rendered for all users acting on `useAuth` but not using it to guard the button. | Wrap action buttons with `canEdit` check (Admin/Manager/Owner only). | DONE |
| Projects | /projects/[id] | app/(dashboard)/projects/[id]/page.tsx | Project Status Control | Permission Issue | Users can change project status without role verification. | Add `canEdit` check to `ProjectStatusControl`. | DONE |
| Tasks | /tasks | components/tasks/TaskDetailSheet.tsx | Delete/Edit Controls | Permission Issue | `TaskDetailSheet` does not check user roles or ownership. Any user can delete or update any task. | Implement `canEdit`/`canDelete` logic based on `assigneeId`, `ownerId`, or role. | DONE |
| Invoices | /invoices/[id] | app/(dashboard)/invoices/[id]/page.tsx | Edit/Mark Paid Actions | Permission Issue | "Edit Invoice" and "Mark Paid" buttons are visible to all users. No role check for creating invoices either. | Restrict Invoice modification/creation to Admin/Manager roles. | DONE |
| Reports | /reports | app/(dashboard)/reports/page.tsx | Revenue Data | Data Privacy | Sensitive financial data (Total Revenue, Forecast) is visible to all authenticated users, including 'Team' role. | Restrict visibility of financial cards/charts to Admin/Manager roles only. | DONE |
| Marketing | /marketing/email | app/(dashboard)/marketing/email-campaigns/[campaignId]/review/page.tsx | Send Campaign Action | Permission Issue | `handleSend` allows any authenticated user to trigger campaign emails. No role check. | Restrict sending campaigns to Admin or Manager roles. | DONE |
| Settings | /settings | app/(dashboard)/settings/page.tsx | Profile/Notification Save | Functional Integrity | The "Save" buttons for Profile, Notifications, and Currency are non-functional (only show toast) and do not persist changes to the backend. | Implement actual API calls/Firestore updates to save user settings. | DONE |
